Project 0, Part 1: Multilayer Perceptrons¶

Fashion-MNIST classification with an MLP implemented in PyTorch. The dataset contains 28×28 grayscale images of clothing in 10 classes, 60,000 training and 10,000 test images. Each image is flattened to a 784-dimensional vector before entering the network.

Task 1: Dataset and baseline model¶

Baseline architecture¶

  • Input: 784 (28×28 flattened)
  • Hidden: 256 units, ReLU
  • Output: 10 logits
  • Loss: cross-entropy (softmax applied internally)
  • Optimizer: SGD, learning rate 0.1
  • Batch size: 256, 10 epochs

Total parameters: 784×256 + 256 + 256×10 + 10 = 203,530.

Results¶

Final epoch: training loss 0.372, validation loss 0.447, validation accuracy 83.5%. Peak validation accuracy was 85.2% at epoch 9.

Training loss decreases monotonically. Validation loss is noisier and spikes at epochs 5 and 8, which is expected with a fixed learning rate of 0.1. The steps are large enough to occasionally overshoot. The gap between training and validation loss stays small, so the model is not meaningfully overfitting at this capacity.

Adding a second hidden layer (784 → 256 → 128 → 10)¶

Final accuracy 78.2%, below the 85.4% baseline. The trajectory is more informative than the final number: the model reached 84.8% at epoch 7, then validation loss jumped from 0.429 to 0.610 at epoch 10 while training loss continued to fall.

This is not evidence that depth hurts in principle. It indicates that a learning rate of 0.1 is too aggressive for the deeper network. Gradients pass through an extra layer of multiplication, and the resulting updates are large enough to destabilize training late in the run. Fashion-MNIST is also simple enough that a single hidden layer nearly saturates what a fully-connected network can extract, so there is little headroom for extra capacity to help.

Hidden layer with one neuron (784 → 1 → 10)¶

Final accuracy 36.8%, with training loss plateauing at 1.49. Random guessing would give 10%, so the model learned something, but it is severely limited.

The cause is an information bottleneck. All 784 pixel values are compressed into a single scalar, and the output layer must separate 10 classes using only that one number. Geometrically, the 10 class regions have to be arranged as intervals along a single line. Any two classes that are not separable by a single threshold on that scalar cannot be distinguished. The failure is structural, not a matter of insufficient training: more epochs cannot recover information the architecture discarded.

Takeaway¶

Capacity is a hard floor but not a reliable lever. Too little width makes a task impossible regardless of training. Additional depth, without retuning the learning rate, can make training less stable rather than more accurate.

Sigmoid vs ReLU, single hidden layer¶

ReLU Sigmoid
Epoch 1 train loss 0.860 1.459
Epoch 10 train loss 0.372 0.482
Epoch 10 val accuracy 83.5% 80.9%

Sigmoid starts much worse and converges more slowly, but it is still improving at epoch 10 and would likely narrow the gap with more training. Its curve is also smoother; ReLU's validation loss fluctuates more because its larger effective gradients produce larger parameter updates.

The mechanism is the derivative. Sigmoid's slope has a maximum of 0.25 and is smaller than that for most inputs, so the error signal passing backward through the activation is scaled down by at least a factor of four. ReLU's derivative is exactly 1 wherever the unit is active, so the signal passes through unchanged. With one hidden layer this costs speed; with many layers it becomes fatal, as shown below.

Vanishing gradients in a deep network¶

Mean absolute weight gradient per layer, measured after a single backward pass on a 7-layer network (layer 1 is closest to the input):

Layer Sigmoid ReLU
1 3.32e-08 1.34e-05
2 1.10e-07 1.06e-05
3 9.35e-07 8.82e-06
4 5.90e-06 9.88e-06
5 4.23e-05 2.00e-05
6 3.16e-04 3.67e-05
7 8.94e-03 4.87e-04

With sigmoid, the gradient shrinks by roughly an order of magnitude per layer moving backward. Layer 7 receives 8.94e-03; layer 1 receives 3.32e-08, a ratio of about 270,000. At a learning rate of 0.1 the first layer's weights move by a negligible amount. Effectively they remain at their random initialization while only the top layers learn.

With ReLU the same span is a factor of roughly 36. Every layer receives a usable signal.

Note that sigmoid's gradients are actually larger than ReLU's at layers 5 through 7. The problem is not magnitude at any single layer but compounding: each backward step through a sigmoid multiplies the signal by that activation's derivative, at most 0.25. Across six layers, 0.25^6 ≈ 2.4e-04. ReLU multiplies by 1 at every active unit, so nothing compounds and the plot on a log scale is nearly flat.

Task 4: Computational considerations¶

Memory during prediction¶

Inference requires two things in memory:

  1. Parameters 203,530 floats for the baseline model, about 0.8 MB at float32. This cost is fixed and independent of batch size.
  2. Activations for the current layer only once the hidden layer's output has been used to compute the logits, those hidden values can be discarded. The same buffer is reused layer by layer.

Inference memory is therefore roughly constant in network depth.

Memory during training¶

Training adds several costs on top of the above:

  1. All intermediate activations are retained. This is the dominant cost. The gradient for a weight is the error signal arriving at its output multiplied by the value that entered it — and that input value is the previous layer's activation. Those activations cannot be freed after the forward pass because the backward pass consumes them. Every layer's output, for every sample in the batch, must persist simultaneously. For one hidden layer at batch size 256 that is 256 × 256 × 4 bytes ≈ 262 KB; the total scales linearly with both batch size and depth.

  2. Gradients — one float per parameter, doubling parameter memory.

  3. Optimizer state — none for plain SGD. Adam maintains two running moment estimates per parameter, tripling parameter memory relative to SGD.

  4. The computational graph — PyTorch records which operations produced which tensors so that backward() can traverse the chain in reverse.

Why training requires more memory than prediction¶

Inference is a one-directional pass in which intermediate results are disposable: once a value has been consumed by the next layer, it can be overwritten. Training is a round trip. The backward pass needs every value the forward pass produced, so nothing can be released until its gradient has been computed.

The practical consequence is that inference memory is approximately flat in depth while training memory grows linearly with it. This is why a model can often be run on hardware that could not possibly train it. Gradient checkpointing addresses this directly by discarding activations during the forward pass and recomputing them during the backward pass, trading additional compute for reduced peak memory.
